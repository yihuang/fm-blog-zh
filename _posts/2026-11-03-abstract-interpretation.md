先看一个很小的 C 函数。

```c
uint8_t frame[256];

void put(uint32_t n) {
    if (n > 0)
        frame[n - 1] = 0;
}
```

`n` 来自配置文件。测试跑过一万组配置，全部通过——因为写测试的人没想到会有人填 1000。只要有人这么填，`frame[n - 1]` 就越界。

这个 bug 不在任何一行上：代码合法，配置也合法，只有两者组合出的那一次运行不合法。

你想说的那句话是：

> 对所有可能的 `n`，这个函数都不会写坏内存。

测试给不了它。一次运行只排除一个点；而这句话要求的是所有点。这不是“测得不够多”，是量词不同：测试给存在命题，静态分析要给全称命题。

**抽象解释**（abstract interpretation）就是给全称命题的一套办法：用有限的东西盖住无限多种运行，并且保证盖住。它不是一个工具，而是一个框架——编译器优化、类型检查、Astrée、你 IDE 里的空指针提示，都是它的实例。1970 年代，Patrick Cousot 和 Radhia Cousot 把它提了出来。

这个系列的第一篇讲“永远”——[liveness 与不动点]({% post_url 2026-10-19-liveness-and-fixed-points %})；上一篇讲“形状”——[拓扑学]({% post_url 2026-10-25-topology-for-computer-scientists %})；这一篇回到程序，讲“所有”。

## 一、测不完的输入

先算一笔账。

一个接收两个 `uint32_t` 的函数，有 2⁶⁴ 种输入。每纳秒试一种，试完也要五百多年。这还只是一个函数；真实的程序有指针、堆、文件、网络、线程调度，状态空间不是一个数字，而是一个指数。

路径也会爆炸。每个 `if` 翻一倍，十个分支就是一千条路径；循环再把路径变成无限多条，因为循环次数本身就是输入。

测试在这个空间里抽样。样本再有代表性，它给出的也只是：

```text
∃ 一组输入：程序没崩。
```

而我们要的是：

```text
∀ 输入、∀ 调度：程序不越界。
```

那能不能直接算？把“所有可能的运行”当成一个数学对象，一次性求出它的性质？

可以，这正是下一节要做的。但先记住一个坏消息：**一般的程序，精确地回答任何非平凡的语义问题都是不可能的**（Rice 定理）。停机问题只是其中最出名的一个。

所以抽象解释从第一天起就不打算“精确回答”。它打算**换一个能回答的问题**，并保证新答案不会把坏情况漏掉。

## 二、把所有运行收进一个集合

对每个程序点 `p`，把能够到达 `p` 的所有状态收起来：

```text
Σ_p = { σ | 存在一条从入口到 p 的执行，到达 p 时状态是 σ }
```

`Σ_p` 叫程序点 `p` 的**收集语义**（collecting semantics）。它不关心某一次运行怎么走，只关心“走到这里时，世界可能长什么样”。整个程序的分析，就是在求这一族集合 `{Σ_p}`。

它满足一组方程。对每个点 `p`：

```text
Σ_p = Init(p) ∪ { σ' | 存在边 q→p 和 σ ∈ Σ_q，
                  σ' = f_{q→p}(σ) }
```

`Init(p)` 是入口处的初始状态（只有入口非空），`f_{q→p}` 是沿着边 `q→p` 执行一条语句（或一次判断）的转移函数。循环让方程出现回边，于是某个 `Σ_p` 会依赖自己——这正是上一篇那个方程：

```text
R* = {s₀} ∪ post(R*)
```

只不过上一次的元素是“状态图里的节点”，这一次是“变量取值的组合”。数学是一样的：在状态集合的幂集上，`f` 单调，所以方程有最小不动点；从空集开始迭代，就能一步步点亮所有可达的状态。

（严格说，这还要求 `f` 连续：并的像等于像的并。可达性算子满足这一点，所以迭代 ω 步就到；一般的单调函数只保证最小不动点存在，不保证这么容易算。）

举个例子：

```text
x = 0
while x < 10:
    x = x + 1
```

在各个点上，精确的 `Σ_p` 是：

| 位置 | `Σ_p` 里所有可能的 `x` |
|---|---|
| 循环前 | `{0}` |
| 循环头，第 1 次 | `{0}` |
| 循环头，第 2 次 | `{0, 1}` |
| … | … |
| 循环头，全部 | `{0, 1, …, 9}` |
| 循环后 | `{10}` |

这个答案完全正确。精确的 `Σ_p` 有什么用？

它不参与计算，但它是所有正确性说法的参照系：

- **定义“对”**：说一个摘要是 sound 的，意思就是它盖住了 `Σ_p`（下一节会写成 `Σ_p ⊆ γ(a)`）。
- **定义“准”**：一个摘要比 `Σ_p` 多盖了多少，就是误报；少盖了多少，就是漏报。
- **定义“往哪边近似”**：每一步抽象转移，都必须盖住这一步真实执行之后的状态。

这有点像数值分析里的“真值”：你算不出它，但误差是相对它定义的。

它不可计算，也不可扩展：

- 如果循环次数来自输入 `n`，集合就是 `{0, …, n}`，大小随 `n` 增长；`n` 无界，集合就无界。
- 真实程序的变量是机器字、指针、数组、堆对象；一个状态本身就可能巨大，状态的集合更不用说。
- 而且对一般程序，这个最小不动点根本算不出来（Rice 定理 again）。

所以，精确的 `Σ_p` 是一个**理想对象**：我们不算它，但没有它，“对”和“精确”都无法定义。

> **冷知识**：Cousot 兄弟 1977 年那篇论文的标题里，同时出现了“construction”和“approximation of fixpoints”——抽象解释从第一天起就是关于不动点的：构造它，或者近似它。

我们需要一个有限的替身。

## 三、摘要：一个元素盖住一族状态

取定一个程序点 `p`。`Σ_p` 是一族具体状态；我们不存这一族，只存“关于这一族状态的一个说法”。

比如，不问 `x` 到底是 0、1 还是 2，只说：

```text
x ∈ [0, 2]
```

一个区间，就概括了一族取值。区间是有限的（两个端点），而它代表的集合可能是无限的。

把这种“说法”的集合叫**抽象域** `A`。`A` 里的一个元素 `a` 就是一个**摘要**。`A` 不是一个随便的集合，而是一个**格**（lattice）：元素之间可以比较谁更精确，两个元素可以合并，有一个“什么都不知道”的顶，也有一个“什么都代表不了”的底。

（中文里“格”既是 lattice 也是 grid；这里说的是前者：一个偏序集，任意两个元素都有最小上界和最大下界。和 Excel 的格子没有关系，但这个双关很适合本文。）

以区间为例：

| 记号 | 含义 | 在区间域里 |
|---|---|---|
| `a ⊑ b` | `a` 比 `b` 精确（`a` 代表的集合更小） | `[l,u] ⊑ [l',u']` 当 `l' ≤ l` 且 `u ≤ u'` |
| `a ⊔ b` | 两个摘要的合并（最小上界） | `[min(l,l'), max(u,u')]` |
| `⊥` | 不可能：代表空集 | 空区间 |
| `⊤` | 什么都不知道：代表所有状态 | `[-∞, +∞]` |

光有格还不够。每个抽象元素必须说清楚它到底代表哪些具体状态。这个解释叫**具体化**（concretization）：

```text
γ([l, u]) = { n | l ≤ n ≤ u }
```

`γ` 把抽象元素映回具体状态的集合。有了它，“这个摘要是否靠谱”才有定义：

```text
健全（sound）：Σ_p ⊆ γ(a)
```

这里三个符号各就各位：`Σ_p` 是某个程序点上的一族具体状态（下标 `p` 只是标记位置；固定 `p` 之后，它就是一个普通集合）；`a` 是抽象域 `A` 里的一个元素，比如区间 `[l, u]`；`γ(a)` 是 `a` 代表的那一族状态。整句话读作：**`a` 代表的状态里，包含了所有真正可能到达 `p` 的状态。**

注意方向：**只能多，不能少**。多出来的部分会产生误报；少掉的部分会产生漏报。前者烦人，后者致命。

一个抽象元素因此是一个**承诺**：它代表的那一族状态，一定盖住了真相。至于盖得多紧，是另一个问题——**精度**。

健全和精度是两根独立的轴：

- 不健全：摘要声称盖住了，实际上漏了——这是实现 bug，不是理论。
- 不精确：`⊤` 永远健全，但它什么也没说。

抽象解释的全部工程，就是在这两根轴之间找平衡。

真实的状态有很多变量。最简单的做法是给每个变量配一个区间，合起来就是一个**抽象状态**——几个域的笛卡尔积。这就是 **product domain** 的最简形式：每个变量各自管自己，互不知道对方的存在。它便宜、好用，也是后面所有例子的基础。

*图 1：左边是具体域里的一族状态 `Σ`（某个 `Σ_p`），右边是抽象域里的一个元素 `a`。`α` 取“能盖住 `Σ` 的最小摘要”，`γ` 把 `a` 解释回一族状态。虚线是 `γ(α(Σ))`：它总是包含 `Σ`，多出来的那圈就是分析器不知道的东西。*

## 四、Galois 连接：什么叫“最精确”

给定一个具体集合 `Σ`（比如某个 `Σ_p`），哪个摘要最好？

定义：

```text
α(Σ) = 所有满足 Σ ⊆ γ(a) 的 a 中最小的那个
```

也就是“能盖住 `Σ` 的最小摘要”。如果这个最小值存在，就得到一对映射 `α` 和 `γ`。由定义，`α(Σ)` 自己就是候选之一：它满足 `Σ ⊆ γ(α(Σ))`，而且是最小的那个。`α` 和 `γ` 之间有一条极其好用的等价关系：

```text
α(Σ) ⊑ a   当且仅当   Σ ⊆ γ(a)
```

为什么？两个方向：

- 若 `Σ ⊆ γ(a)`，那么 `a` 就是定义里那个候选集合的一员；`α(Σ)` 是其中最小的，所以 `α(Σ) ⊑ a`。
- 若 `α(Σ) ⊑ a`，由 `α(Σ)` 本身满足 `Σ ⊆ γ(α(Σ))`（它是候选之一），再用 `γ` 单调，得 `Σ ⊆ γ(a)`。

这条等价关系叫 **Galois 连接**，记作 `α ⊣ γ`。它的意思是：**“`a` 盖住了 `Σ`”这句话，可以在具体域里说（`Σ ⊆ γ(a)`），也可以在抽象域里说（`α(Σ) ⊑ a`）；两种说法永远同真同假。** 抽象域里的比较，是具体域里的包含的一种压缩写法。

拿区间试一下。取 `Σ = {1, 3}`，则 `α(Σ) = [1, 3]`：

| 摘要 `a` | `α(Σ) ⊑ a` | `Σ ⊆ γ(a)` |
|---|---|---|
| `[0, 5]` | `[1, 3] ⊑ [0, 5]` ✓ | `{1, 3} ⊆ [0, 5]` ✓ |
| `[2, 5]` | `[1, 3] ⊑ [2, 5]` ✗ | `{1, 3} ⊆ [2, 5]` ✗ |

两列永远一致。这不是巧合：`α` 被定义成“最小的”，所以它恰好是那座桥。

从这条等价出发，四条性质自动成立：

- `α` 和 `γ` 都单调：更大的集合得到更大的摘要，更大的摘要代表更大的集合。
- `Σ ⊆ γ(α(Σ))`：先抽象再解释回来，只会变大，不会变小。
- `α(γ(a)) ⊑ a`：先解释再抽象，只会更精确，不会更粗。
- `α` 是“最好的”：任何其他能盖住 `Σ` 的摘要 `b`，都满足 `α(Σ) ⊑ b`。

在区间域里，`α` 有非常具体的形式：

```text
α(Σ) = [min Σ, max Σ]        （Σ 非空）
α(∅) = ⊥
```

“最好的区间”就是所有点的最小值和最大值。多一个点，区间就宽一点；这是区间域能做到的极限。

这里要小心一个常见的误解：`γ` 不是 `α` 的逆。`γ(α(Σ))` 通常严格大于 `Σ`（区间里塞进了没出现过的值）；`α(γ(a))` 通常严格小于 `a`（一个区间可能根本没被任何真实状态“用满”）。两个方向的缝隙，正好对应两种精度损失：

- `γ(α(Σ)) \ Σ`：抽象带来的**过近似**，误报的来源。
- `a \ α(γ(a))`：域里**用不上的精度**，白付的成本。

> 抽象解释不是“随便近似一下”。`α` 定义了“在这个域里，什么叫最精确”；没有 `α`，你甚至不知道自己丢了多少。

最后一句诚实话：不是每个抽象域都有 `α`。有些域只能给出 `γ` 和一个局部健全的转移函数，工具照样跑得很好——因为没有 `α` 不影响健全性，只影响“能不能声称自己最精确”。

## 五、在摘要上执行程序

有了摘要，就可以“在摘要上执行程序”了。

对每条语句，定义一个**抽象转移函数** `f#`，它吃一个摘要、吐一个摘要。唯一的要求是**局部健全**：

```text
对所有 a：f(γ(a)) ⊆ γ(f#(a))
```

翻译一下：如果 `a` 盖住了进入这条语句之前的所有状态，那么 `f#(a)` 必须盖住执行之后的所有状态。`f#` 可以很粗——粗到直接返回 `⊤` ——只要它不撒谎。

用 Galois 连接改写，这个条件就是：

```text
α(f(Σ)) ⊑ f#(α(Σ))
```

抽象转移可以比“先具体执行、再抽象”更粗，但不能更细。图 2 画的就是这个不等式：方框不要求交换，只要求“抽象的那条路走在上面”。

几个例子。

**赋值 `x := x + 1`。** 在区间上：

```text
f#([l, u]) = [l + 1, u + 1]
```

**赋值 `x := y * z`。** 在符号域上，可以枚举符号的乘法表；在区间域上，取四个端点的乘积的最小/最大值。两者都不精确（它们丢掉了 `y` 和 `z` 的相关性），但都健全。

**分支 `if x >= 0`。** 如果只把两条分支的摘要合并，`x` 的信息就丢了。所以还要一个动作：**守卫细化**（guard refinement）。在 then 分支里，把 `x` 的下界抬到 0；在 else 分支里，把上界压到 -1。这一步不改变“所有可能状态”的集合，只是让摘要更紧——它是精度的主要来源之一。

于是每条语句只有三种基本动作：

1. **转移**：按语句的语义更新摘要。
2. **细化**：用分支条件收窄摘要。
3. **合并**：在控制流汇合处取 `⊔`。

把这三种动作串起来，就得到了一个抽象的“解释器”。它不运行程序，它运行程序的摘要。

现在到了关键的一步：**为什么一条语句的保证，能变成整个程序的保证？**

答案是归纳。设 `Σ_n` 是第 `n` 轮迭代得到的真实状态集合，`a_n` 是对应的摘要。假设 `Σ_n ⊆ γ(a_n)`。那么：

```text
f(Σ_n) ⊆ f(γ(a_n)) ⊆ γ(f#(a_n))
```

第一个 `⊆` 用了 `f` 的单调性，第二个用了局部健全。也就是说，只要这一步之前盖住了，这一步之后也盖住。初始状态显然盖住；每一步都保持；取并之后仍然盖住。归纳法把“每条语句”变成了“整个程序”。

这个证明很短，但它是整个领域的支点：**你只需要为每条语句的转移函数负责，剩下的交给归纳法。**

![局部健全，全局健全]({{ '/images/ai-02-square.png' | relative_url }})
{: .post-figure}

*图 2：抽象的交换图。只要 `α(f(Σ)) ⊑ f#(α(Σ))`，具体的一条边就被抽象的一条边盖住；把这个事实对每条边、每一轮迭代重复，就得到整个程序的不动点也被盖住。*
{: .caption}

注意这里藏着一个要求：`f#` 必须**单调**。如果 `a ⊑ b` 但 `f#(a) ⋢ f#(b)`，上面的归纳就断了。真实的分析器会小心地保证单调性；这也是为什么“在转移函数里偷偷做点聪明事”很危险。

## 六、循环：不动点又回来了

程序里的循环，在方程里是一条回边。回边意味着摘要要“喂回自己”：

```text
循环头的摘要 = 进入循环的摘要 ⊔ f#(循环头的摘要)
```

或者更常见地写成迭代：

```text
a₀ = ⊥
a_{n+1} = a_n ⊔ f#(a_n)
```

因为 `f#` 单调，这个序列只升不降。它什么时候停？

如果抽象域**高度有限**——也就是说，不存在无限长的严格上升链——那么它一定在有限步内停。停下来的 `a` 就是最小不动点，也是这个域能给出的最精确的答案。

符号域就是这样一个域。它的八个元素（`⊥`、`-`、`0`、`+`、`≤0`、`≥0`、`≠0`、`⊤`）排成一张有限高度的图：

```text
⊥ < - < ≤0 < ⊤
⊥ < 0 < ≥0 < ⊤
⊥ < + < ≥0 < ⊤
...
```

最长的一条链只有四个元素，所以任何上升序列最多走三步。

区间域不是。`[0,0] ⊏ [0,1] ⊏ [0,2] ⊏ …` 是一条无限长的严格上升链。一个从 0 数到 `n` 的循环，如果 `n` 无界，迭代就永远不会停：

```text
i = 0
while i < n:
    i = i + 1
```

摘要会依次变成 `[0,0]`、`[0,1]`、`[0,2]`……每一轮都比上一轮宽一点，永远差一步。

这不是实现得不好，而是区间这个域的形状决定的。**终止性不是运气，是格的高度。**

![有限高度与无限高度]({{ '/images/ai-03-lattices.png' | relative_url }})
{: .post-figure}

*图 3：左边是符号格，高度 3，迭代必然停；右边是区间格，高度无限，`[0,k]` 可以一直宽下去。要让它停，必须换一条上升链。*
{: .caption}

面对无限高度，有两条路：

1. 换一个高度有限的域。精度低，但保证停。
2. 留在区间域，但把上升链**剪断**。这就是 widening。

## 七、widening：用精度换终止

widening 是一个算子 `∇`，它吃两个摘要，吐一个更大的摘要，并且保证按它迭代时，上升链不会无限跑下去。

在区间上，它的规则简单到粗暴：

```text
[l, u] ∇ [l', u'] = [ l  if l ≤ l'  else -∞,
                      u  if u' ≤ u  else +∞ ]
```

也就是说：下界只要往下动过，就直接跳到 `-∞`；上界只要往上动过，就直接跳到 `+∞`。它不试图逼近，它直接放弃。

但放弃也得有底线：`∇` 必须同时盖住两个输入，即 `a ⊑ a ∇ b` 且 `b ⊑ a ∇ b`。否则它会把真实状态丢掉，健全性就没了。widening 可以粗，不可以错。

看那个数到 `n` 的循环：

| 轮次 | 循环头的 `i` | 发生了什么 |
|---|---|---|
| 0 | `[0, 0]` | 初始 |
| 1 | `[0, 1]` | 走一圈 |
| 2 | `[0, 2]` | 再走一圈 |
| 3 | `[0, 3]` | 延迟 widening：前几轮先精确算 |
| 4 | `[0, +∞]` | 上界动过，`∇` 直接跳到顶 |
| 5 | `[0, +∞]` | 不动点，停 |

几轮之内收敛。代价是 `i` 的上界没了：分析器现在只知道 `i ≥ 0`。

这件事听起来很亏，但它是**健全**的：每一步仍然是真实状态的上界，只是上界变松了。抽象解释要的从来不是“最小不动点”这个理想答案，而是**任何一个可证明的后不动点**（post-fixpoint）：

```text
f#(a) ⊑ a
```

只要 `a` 满足这个式子，`a` 就是一个归纳不变式，就能拿来证明性质。最小的那个只是“最好的后不动点”，不是唯一合法的答案。

> widening 把“求最小解”换成了“求一个可验证的解”。这是一个典型的工程交易：放弃最优，换来确定性。

> **深水区**：完整的抽象解释理论并不要求 Galois 连接。只要有一个具体化映射 `γ` 和一族单调的抽象转移，健全性就能定义；widening 甚至不是 Galois 连接的一部分，它是为了终止额外加的“加速器”。这就是为什么工业工具说的是“抽象解释 + widening”，而不是“一个 Galois 连接”。

代价还不止于此。回到开头那个循环：

```text
i = 0
while i < 1000:
    i = i + 1
```

widening 之后，循环头是 `i ∈ [0, +∞]`。循环体里的守卫 `i < 1000` 会把它细化成 `[0, 999]`，所以**循环体内部**的检查往往还是准的；但循环**之后**，出口只告诉你 `i ≥ 1000`，上界仍然是 `+∞`。任何需要 `i ≤ 1000` 的检查都会误报。

怎么把上界捡回来一点？两个常用手段。

**narrowing（窄化）。** 在 widening 收敛之后，再跑几轮“向下”的迭代：

```text
a_{n+1} = a_n ⊓ f#(a_n)
```

`⊓` 是格的交（在区间上是取交集）。只要每一步下探之后仍然是后不动点（标准实现会保证这一点），它就不会把摘要变得比真实状态更小，却能把 widening 跳过头的那部分收回来。

**阈值（threshold）。** 不要一上来就跳到 `+∞`，先跳到程序里出现过的常量：1000、256、数组长度。区间会变成 `[0, 1000]`，而不是 `[0, +∞]`。Astrée 的论文里专门提到了带阈值和延迟的 widening 策略（"widening strategies with thresholds, delayed"）——这不是学术装饰，而是工业分析器能不能用的分水岭。

```text
没有 widening：永远不收敛
有 widening：收敛，但可能跳过头
加 narrowing / 阈值：跳过头的那部分，捡回来一些
```

![widening 把上升链剪断]({{ '/images/ai-04-widening.png' | relative_url }})
{: .post-figure}

*图 4：前几轮精确，第 4 轮 `∇` 直接跳到 `+∞`；阈值或 narrowing 再把上界收回一个有限值。收敛性和精度，在这里是一对反比。*
{: .caption}

## 八、精度从哪里漏掉

到此为止，框架已经完整了。你会发现它给出了一个**健全但可能很粗**的答案。粗在哪里？只有三个地方。

**第一，合并（join）。** 控制流一汇合，两个分支的摘要就要取上界：

```text
x = 1        →  x ∈ [1, 1]
x = 2        →  x ∈ [2, 2]
汇合          →  x ∈ [1, 2]
```

`x` 其实只可能是 1 或 2，但区间说不出“离散的两个点”，只能说“1 到 2 之间”。更糟的是相关性：如果两个变量总是一起变（`x = y`），区间会分别记住它们的范围，然后把组合空间放大成一个盒子——盒子里有很多点根本到不了。

![合并与相关性]({{ '/images/ai-05-precision.png' | relative_url }})
{: .post-figure}

*图 5：左：两条路径合并成 `[1,2]`，丢掉了“只可能是 1 或 2”。右：`x = y` 的对角线被区间放大成一个盒子，角上的点不可达，但分析器以为可能——这是误报最典型的来源。*
{: .caption}

**第二，域的表达力。** 区间说不出 `x ≠ 0`，说不出 `x < y`，也说不出 `i < n`。这些关系恰好是数组越界、除零、指针别名最需要的。换更强的域（八边形、多面体）能表达其中一部分，代价是每次转移都更贵。

**第三，widening。** 前面已经看到了：它为了终止，主动放弃上界。

三个漏洞对应三类对策：

| 漏洞 | 对策 | 代价 |
|---|---|---|
| 合并丢相关性 | 关系域（八边形、多面体）、路径敏感 | 转移函数变贵；路径敏感还可能爆炸 |
| 域说不清 | 选更贴性质的域（数组长度、指针形状、字符串） | 每个域都要单独实现、单独证明健全 |
| widening 过头 | 阈值、延迟 widening、narrowing | 要选阈值；精度取决于常量选得准不准 |

工程上最有用的一句话是：**误报几乎总能归到这三处之一。** 看到一条报警，先问“是哪一步把信息弄丢了”，比换一个工具更有用。

举一个具体的例子。要证明 `a[i]` 安全，需要 `0 ≤ i < 10`。如果代码是：

```c
if (0 <= i && i < 10)
    a[i] = 0;
```

守卫细化就能把 `i` 收窄到 `[0, 9]`，分析器直接通过。但如果 `i` 来自 `while (i < n)`，而 `n` 的上界未知，区间就只能给出 `i ∈ [0, +∞]`——这时报警不是分析器笨，而是它真的不知道 `n` 有多小。想让它们通过，要么给 `n` 加一个上界（阈值/断言），要么换一个能记住 `i < n` 的域。

## 九、写一个一百多行的分析器

理论讲完了，把它跑起来。

下面这个分析器只支持四种语句（赋值、if、while、数组边界检查）和四种表达式（常量、变量、加法、除法），没有解析器——程序直接写成 Python 的元组。但循环、守卫细化、widening、报警，一个都不少。

**第一部分：摘要与转移。** 区间、join、widen、守卫细化。注意 `empty` 表示 `⊥`（不可达），`TOP` 表示 `⊤`（什么都不知道）。

```python
from dataclasses import dataclass
from math import inf

# ---------- 1. 摘要：区间格 ----------
@dataclass(frozen=True)
class Iv:
    lo: float
    hi: float
    @property
    def empty(self):
        return self.lo > self.hi

TOP = Iv(-inf, inf)

def join(a, b):                      # 两条路径取“共同的上界”
    if a.empty: return b
    if b.empty: return a
    return Iv(min(a.lo, b.lo), max(a.hi, b.hi))

def widen(a, b):                     # 只往上跳，从不回头
    if a.empty: return b
    return Iv(a.lo if b.lo >= a.lo else -inf,
              a.hi if b.hi <= a.hi else  inf)

def add(a, b): return Iv(a.lo + b.lo, a.hi + b.hi)

# ---------- 2. 抽象状态与转移 ----------
def join_st(a, b):
    if a is None: return b
    if b is None: return a
    keys = a.keys() | b.keys()
    return {x: join(a.get(x, TOP), b.get(x, TOP)) for x in keys}

def widen_st(a, b):
    if a is None: return b
    keys = a.keys() | b.keys()
    return {x: widen(a.get(x, TOP), b.get(x, TOP)) for x in keys}

def ev(e, st):
    k = e[0]
    if k == "const": return Iv(e[1], e[1])
    if k == "var":   return st.get(e[1], TOP)
    if k == "add":   return add(ev(e[1], st), ev(e[2], st))
    return TOP                                   # 商不建模，只检查分母

def check_div(e, st, alarms):
    if e[0] == "div":
        d = ev(e[2], st)
        if d.lo <= 0 <= d.hi:
            alarms.append(f"除零：分母 ∈ {show(d)}")
        check_div(e[1], st, alarms)
        check_div(e[2], st, alarms)

def guards(cond, yes, st):          # if / while 的守卫让摘要变窄
    op, x, k = cond
    a = st.get(x, TOP)
    lo, hi = a.lo, a.hi
    if op == ">=":
        lo, hi = (max(lo, k), hi) if yes else (lo, min(hi, k - 1))
    if op == "<":
        lo, hi = (lo, min(hi, k - 1)) if yes else (max(lo, k), hi)
    return {**st, x: Iv(lo, hi)}

def step(stmt, st, alarms):
    if stmt[0] == "assign":
        check_div(stmt[2], st, alarms)
        return {**st, stmt[1]: ev(stmt[2], st)}
    if stmt[0] == "bounds":
        i = ev(stmt[1], st)
        if not (0 <= i.lo and i.hi < stmt[2]):
            alarms.append(f"越界：i ∈ {show(i)}，数组长 {stmt[2]}")
    return st

def show(a):
    f = lambda v: "+∞" if v == inf else "-∞" if v == -inf else f"{v:g}"
    return f"[{f(a.lo)}, {f(a.hi)}]"
```

**第二部分：CFG 与不动点。** 结构化的 `if` / `while` 在这里被摊平成一张图；`head` 标记循环头，只有循环头才用 widening，其余汇合点用 join。工作列表（worklist）从入口开始，谁的状态变了就把谁的后继重新入队。

```python
# ---------- 3. 从语句到 CFG ----------
class CFG:
    def __init__(self):
        self.nodes = []      # [语句, 后继, 是否循环头]
    def add(self, stmt, head=False):
        self.nodes.append([stmt, [], head])
        return len(self.nodes) - 1
    def link(self, src, dst, cond=None, yes=True):
        self.nodes[src][1].append((dst, cond, yes))
    def build(self, body, nxt):
        for s in reversed(body):
            nxt = self.one(s, nxt)
        return nxt
    def one(self, s, nxt):
        if s[0] == "if":
            n = self.add(("skip",))
            self.link(n, self.build(s[2], nxt), s[1], True)
            self.link(n, self.build(s[3], nxt), s[1], False)
            return n
        if s[0] == "while":
            h = self.add(("skip",), head=True)
            self.link(h, self.build(s[2], h), s[1], True)
            self.link(h, nxt, s[1], False)
            return h
        n = self.add(s)
        self.link(n, nxt)
        return n

def analyze(body, init):
    cfg = CFG()
    entry = cfg.build(body, cfg.add(("exit",)))
    state, work, alarms = {entry: init}, [entry], []
    while work:
        n = work.pop()
        out = step(cfg.nodes[n][0], state[n], alarms)
        for m, cond, yes in cfg.nodes[n][1]:
            s = guards(cond, yes, out) if cond else out
            old = state.get(m)
            new = (widen_st(old, s) if cfg.nodes[m][2] and old is not None
                   else join_st(old, s))
            if new != old:
                state[m] = new
                work.append(m)
    return cfg, state, sorted(set(alarms))
```

**第三部分：三个程序。** 一个真的会除零，一个被守卫保护，一个会让 widening 跳到无穷。

```python
# ---------- 4. 三个程序 ----------
DIV = [("if", (">=", "x", 0),
        [("assign", "y", ("div", ("const", 10), ("var", "x")))], [])]

BOUNDS = [("if", (">=", "i", 0),
           [("if", ("<", "i", 10),
             [("bounds", ("var", "i"), 10)], [])], [])]

LOOP = [("assign", "i", ("const", 0)),
        ("while", ("<", "i", 1000),
         [("assign", "i", ("add", ("var", "i"), ("const", 1)))])]

def report(name, body, init):
    cfg, state, alarms = analyze(body, init)
    print(f"{name}: {alarms[0] if alarms else '无报警'}")
    for i, node in enumerate(cfg.nodes):
        if node[0][0] == "bounds":
            print(f"        检查点 i ∈ {show(state[i]['i'])}")
        if node[2]:
            print(f"        循环头 i ∈ {show(state[i]['i'])}")

report("div", DIV, {})
report("bounds", BOUNDS, {})
report("loop", LOOP, {})
```

运行结果：

```text
div: 除零：分母 ∈ [0, +∞]
bounds: 无报警
        检查点 i ∈ [0, 9]
loop: 无报警
        循环头 i ∈ [0, +∞]
```

三段输出，正好对应三个概念。

**`div`：真报警。** 入口时 `x` 是 `⊤`；守卫 `x >= 0` 把下界抬到 0，于是分母落在 `[0, +∞]`，包含 0。这个报警是真的：`x = 0` 时确实会除零。分析器不是算命，它只是把所有可能的分母都列了出来。

**`bounds`：守卫细化救了它。** `0 <= i` 把下界抬到 0，`i < 10` 把上界压到 9。检查点处 `i ∈ [0, 9]`，于是 `a[i]` 安全。如果删掉任意一个守卫，报警立刻出现。

**`loop`：widening 的代价。** `i` 从 `[0, 0]` 出发，上界每轮加一，`∇` 在几轮之后把它推到 `[0, +∞]`。循环体里的 `i < 1000` 还能把它细化回 `[0, 999]`；但循环之后，分析器只剩 `i ≥ 1000`。如果后面有一句 `assert(i <= 1000)`，它会误报——而 narrowing 或阈值能把 `[1000, 1000]` 找回来。

这段代码缺什么？几乎什么都缺：没有机器整数的回绕，没有堆和指针，没有函数调用和递归，没有浮点，没有并发，没有数组内容的建模，没有解析器。真实的工业分析器，八成代码都花在这些“簿记”上，而不是花在 `join` 和 `widen` 上。

但它有骨架。骨架对了，剩下的都是工程量。

> **一个容易被忽略的工程问题**：怎么知道分析器自己是健全的？答案不是“读代码”，而是**差分测试**：在一个小到可以穷举的输入域上，把分析器的结论和真实解释器的运行结果对齐——它说“安全”的每一个输入都不能崩；它报的每一条报警，都要能找到一个让它发生的输入（或者明确标记为误报）。一个漏报就足以毁掉整个工具的信任。

## 十、真实世界：从飞控到类型系统

抽象解释不是实验室玩具。它最著名的应用，是空客的飞控软件。

Astrée 是 Patrick Cousot 等人做的静态分析器，目标是证明**没有运行时错误**：不越界、不除零、不溢出。它在空客 A340 的主飞控软件（十余万行 C）上跑出了接近零误报的结论——这件事的意义不在于“找到了几个 bug”，而在于**对一套已经在服役的飞控软件，给出了一个全称的保证**。

Astrée 的关键不是某个神奇的算法，而是三件事的组合：

- **针对性质的域**：区间、八边形、椭圆、决策树，各自负责一类不变式；浮点运算还要把舍入误差建模进去。
- **针对程序的调参**：同一个分析器，换一组参数去适配同一家族的飞控软件（论文里叫 parametrization）。
- **针对规模的不动点实现**：worklist、增量、缓存、分区。

这三件事，没有一件是“纯理论”。抽象解释提供的是**骨架和正确性证明**，工程提供的是**精度和速度**。

同样的骨架也藏在你每天用的东西里。

**编译器优化。** 常量传播、死代码消除、边界检查消除、自动向量化，背后都是“在某个抽象域上算出一个事实，然后用它改写程序”。编译器必须保证这个事实是 sound 的——否则就是错误编译。C 语言的有符号溢出是 UB，编译器据此假设“溢出不会发生”；这条假设本身就是一个抽象域里的前提，只是它把责任推给了程序员。

**类型系统。** 类型检查器是抽象解释的一个特例：类型就是抽象域，类型规则就是转移函数，`Γ ⊢ e : τ` 就是“摘要”。Cousot 在 1997 年的 POPL 上专门讲过这件事（*Types as Abstract Interpretations*）。类型系统通常不做不动点迭代，因为它故意把分析做得“语法导向、流不敏感”；一旦你要求流敏感（比如 TypeScript 的控制流分析、Rust 的借用检查），不动点就回来了。

**Bug 查找工具。** Infer、Clang Static Analyzer 这类工具也是抽象解释的亲戚，但它们做了一个不同的交易：**放弃健全性，换规模和低误报**。它们只报“很可能是 bug”的地方，允许漏掉一些真 bug。

这就引出了工程上最重要的一个区分：

| 维度 | 验证型（sound） | 找 bug 型（unsound） |
|---|---|---|
| 目标 | 证明“没有坏事” | 找出“可能的坏事” |
| 漏报 | 不允许（是 bug） | 允许（是取舍） |
| 误报 | 尽量少，但可接受 | 尽量少，否则没人用 |
| 规模 | 小到中等，可调参 | 大，跑在 CI 里 |
| 例子 | Astrée、Polyspace | Infer、Clang SA |

选型时先问自己：你要的是一张**证书**，还是一张**线索清单**？这两个问题的答案，决定了你应该用哪一类工具，也决定了你应该怎样对待它的报警。

{: .post-figure}

*图 6：一个分析器的五段。前端把源码变成 CFG；转移函数和抽象域负责“一条语句”的语义；不动点引擎负责“所有路径、所有轮次”；最后是报警与优化事实。误报太多时，调的是域和 widening，而不是不动点本身。*

## 十一、怎么选一个抽象

抽象解释的框架是通用的，但**域的选择是具体的**。选错了域，再正确的实现也证不出你想要的性质。

可以用五个问题来选。

**第一，你要证的性质，形状是什么？** 性质决定域：

| 要证的性质 | 合适的域 |
|---|---|
| 不除零、不越界 | 区间、八边形（需要变量之间的关系） |
| 空指针、别名 | points-to / 形状分析 |
| 数据竞争 | 线程模型 + happens-before |
| 信息流不泄露 | 依赖关系 / 安全类型 |
| 资源不泄漏 | 计数抽象（最多打开几个文件） |

没有“万能域”。一个域能表达的，恰好是它语言里的那些形状；性质不在这个形状里，就证不出来。

**第二，你的误报预算是多少？** 验证型工具要求“没有漏报”，所以必须 sound，必须接受误报，然后用调参和分诊把误报压下去。找 bug 型工具反过来：宁可漏，不可烦。这不是技术优劣，是产品定位。

**第三，代码多大、CI 有多少时间？** 抽象解释的复杂度大致是“程序点 × 域的高度 × 转移成本”。百万行代码、每次提交都要跑，和十万行、一晚上跑一次，能选的域完全不同。工程上的常见解法是分层：先跑便宜的域，只在可疑点上升级到贵的域。

**第四，需要跨过程、堆、并发吗？** 这三件事每加一件，分析器的复杂度就上一个台阶。过程间分析要么做上下文敏感（贵），要么做函数摘要（要设计摘要域）；堆要么做形状分析，要么做保守的“所有指针可能指向所有对象”；并发要么做线程模块化（thread-modular），要么直接放弃精度。

**第五，怎么知道分析器自己是对的？** 这是最容易被跳过的一步。三个实用手段：

- **差分测试**：在小输入域上穷举，把“分析器说安全”和“解释器实际运行”对齐。
- **报警可复现**：每条报警都要能给出一组触发它的输入，否则它不可信。
- **假设审计**：分析器里的每一条 `assume`（“这个指针非空”“这个长度小于 256”）都要有 owner，都要能被测试或证明。

最后一条值得展开。工业分析里最常见的“假安全”，不是算法错了，而是**假设错了**：为了让分析通过，有人在代码里加了 `assume(n <= 256)`，而这个假设来自一个调用方的口头承诺。抽象解释会把这条假设当成真理，然后愉快地证明一切安全——它没有撒谎，它只是相信了你。

assume 是一条**证明义务的转移**：你把“n ≤ 256”从分析器手里接了过来。接过来，就要负责。

## 十二、带走一张地图

把全文压缩成一张对照表：

| 你熟悉的东西 | 抽象解释里的名字 | 一句话 |
|---|---|---|
| 一次运行 | 具体状态 | 程序点 + 变量取值 |
| 所有运行 | 收集语义 | 状态集合，一个最小不动点 |
| 类型 | 抽象域元素 | 一族状态的有限表示 |
| 类型规则 | 转移函数 | 每条语句的 sound 近似 |
| 分支合并 | join | 取共同上界，丢掉相关性 |
| 循环 | 不动点 | 回边让方程递归 |
| 强制收敛 | widening | 剪断无限上升链 |
| 事后修正 | narrowing | 把跳过头的那部分收回来 |
| 误报 | `γ` 多出来的部分 | 抽象的代价 |
| 漏报 | `γ` 少掉的部分 | 不健全，是 bug |

如果只带走五句话：

1. **程序分析要算的是“所有运行的状态集合”，它是一个最小不动点。** 测试给的是存在命题，分析给的是全称命题；两者的差别是量词，不是努力程度。
2. **抽象域用一个元素盖住一族状态；健全性是单向的 `Σ_p ⊆ γ(a)`。** 误报是它的影子，漏报是它的反面——前者烦人，后者致命。
3. **Galois 连接定义了“这个域里最精确的答案”。** 转移函数只需要局部健全，归纳法把“每条语句”变成“整个程序”。
4. **循环可能让不动点不收敛；widening 用精度换终止，narrowing 再捡回一点。** 抽象解释求的不是最小解，而是任何可验证的后不动点。
5. **精度只从三处漏：合并、域、widening。** 看到误报，先定位是哪一处，比换一个工具更有用。

## 尾声：它不知道的事

回到开头那个函数。

如果分析器告诉你 `n ∈ [1, 256]`，它证明了对所有调用都安全。如果它告诉你 `n ∈ [1, +∞]`，它没有证明——但它也没有撒谎。它只是不知道。

这句话是抽象解释的伦理：**它从不假装知道得更多。**

它把“不知道”明确地写成 `⊤`，把“到不了”明确地写成 `⊥`，把“我知道一点”写成一个区间、一个八边形、一个多面体。它不隐藏自己的无知，而是把无知放在你能看见的地方。

第一篇把“永远”变成了方程；这一篇把“所有”变成了方程。两台机器是同一台：从一个递归的定义出发，在格上迭代，直到不再变化。人类看不见无限，但可以给它拍一张有限的照片——然后诚实地标注：哪些地方是清晰的，哪些地方是模糊的。

下次遇到一条莫名其妙的误报，别急着关掉工具。先问：**它在哪一步把信息弄丢了？** 是合并了一个分支，是域说不出那个关系，还是 widening 跳过了头？

答案通常就在这三个里面。
